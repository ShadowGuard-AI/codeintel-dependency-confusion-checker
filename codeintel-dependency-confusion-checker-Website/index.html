The Flat Water Is the Warning

It identifies potential dependency confusion attacks by checking for inconsistencies between locally installed packages and those available in public repositories. In the code as it stands that means taking the installed set from importlib.metadata, lower casing each name as its key, and asking the public index, one subprocess per package, what pip index versions reports for that name, then parsing the newest version out of the first line of that answer, or out of the Available versions line beneath it, and comparing the two versions with packaging.version.

The rule is narrow and this page does not widen it: a package is reported as a potential confusion only where the locally installed version is strictly newer than the version the public index answers with. A package that the index does not answer for at all is not folded into that finding but is counted separately, as not found.

Usage, the Placeholder and the Parser Line

python3 main.py [-p PACKAGE] [-r PYPI_URL] [-v]

That is the invocation the argument parser in main.py actually accepts, labelled here as taken from the code. Under it, the line the README does print:

./codeintel-dependency-confusion-checker [params]

No file of that name is the entry point, and the bracketed word is a placeholder and not an argument the program knows.

Newer Here Than There, the Arguments in Parser Order

-hShows a help message and exits.
-p, --packageThe name of the package to check, for example my_package. If it is not provided all installed packages are checked.
-r, --pypi_urlThe base address of the PyPI repository, with a default of https://pypi.org/pypi/.
-v, --verboseEnables verbose output for debugging, which in the code raises the logging level to DEBUG.

Named but Not Installed

A package named with -p is kept for checking even when it is not installed at all, its installed version being held as None, so a name the machine never installed can still be reported. And because the installed set is keyed on lower cased names, two distributions whose names differ only in case would overwrite one another in that set, with only the last version read surviving into the check.

Read All Three Counts Together

Every run prints a closing summary of the form Summary: checked=N failed=N not_found=N. Packages the index did not answer for are also printed as a named class under the heading Packages not found on the public index.

Absent from the Public Index Is Its Own Finding

An internal name that no public index carries is a different kind of fact from a local version that has outrun the public one. Read the summary counts and the not found list together, since either one alone will mislead.

Exit 1 Has Three Different Causes

The run exits 1 where any potential confusion is found, where any check failed, or where nothing could be checked at all, including the early case in which no packages are found to check, which prints a summary of zeroes and exits 1. The line saying that no potential vulnerabilities were found is printed only for a run whose checks completed.
